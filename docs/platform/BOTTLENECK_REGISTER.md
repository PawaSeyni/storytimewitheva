# Architecture Review and Bottleneck Register (S8-001)

Sprint 8 is evidence-gated. Every row below cites a measurement from `BASELINE_2026-09.md`
(reproduce with `node scripts/bench-build.mjs`, `node scripts/bench-search.mjs`, `npm audit`,
`npm outdated`). A row without a threshold breach is recorded as "no action" on purpose.

| ID | Area | Evidence | Verdict | Owner |
|---|---|---|---|---|
| BR-01 | **Prerender time** | 222 routes in 154 s locally (98% of the 168 s build); 0.7 s/route. A 4-page pool gave 151 s and an 8-page pool 137 s, so rendering is CPU-bound in Chrome, not I/O-bound; the pool was measured and NOT kept. Netlify reports 52 s for the same deploy (cached Chromium, faster CPU). | Watch. Threshold: Netlify build > 5 min or > 600 routes. Options then: render only changed routes (content hash per route), or split the catalog build. | engineering |
| BR-02 | **Prerender determinism** | Sequential runs differ on 6 of 224 HTML files: `activities/bingo` and `activities/puzzles` × 3 languages render a random card or puzzle at build time (Netlify logs "3 generated pages changed" on content-free deploys). All other routes are byte-identical run to run. | Fix in Sprint 8 (S8-006): seed the prerender render deterministically or render a fixed first state; a non-deterministic page defeats the "only changed files uploaded" deploy path and cache. | engineering |
| BR-03 | **Deploy artifact weight** | dist = 98 MB: Pinterest pin PNGs 48.9 MB (29 files, ~2 MB each, served with CORS for Pinterest), covers 5.7 MB, PDFs 20.7 MB, everything a visitor loads for a page ≈ 1 MB. Pins and PDFs are 71% of the artifact and 0% of page weight. | Media policy (S8-005): pins are campaign assets, not site assets; keep them out of the page budget, compress on upload, and decide whether they belong in the repo at all. No page-weight breach. | owner + engineering |
| BR-04 | **JavaScript budget** | 791 KB raw / 276 KB gzip across 33 chunks; entry chunk 118 KB gzip; largest lazy page (Resources) 23 KB gzip. Lighthouse mobile (Netlify plugin, this deploy): Performance 96 home, 71 `/books`, 86 activities, 80 about; Accessibility/Best Practices/SEO 100. | `/books` at 71 is the one page below 80: 20 covers on one grid. Budget policy (S8-021) sets entry ≤ 130 KB gzip, page chunk ≤ 40 KB gzip, LCP ≤ 2.5 s. `/books` cover loading is the first optimisation candidate. | engineering |
| BR-05 | **Search** | 74 records, 76 KB JSON, 0.10 ms/query; at 10× 0.98 ms, at 50× 4.7 ms (linear scan, no index structure). The index ships inside the app bundle. | No action. Threshold for an ADR revisit: > 2,000 records or > 20 ms p95 on a mid-range phone, or relevance defects in analytics. See ADR-005. | engineering |
| BR-06 | **Dependencies** | 7 runtime + 20 dev direct deps, 249 installed. `npm audit`: 13 findings (6 high) before, 4 after the non-breaking `npm audit fix` (this PR); the remaining 4 are vite 5 / esbuild (dev-server-only advisories) and react-router 6 open-redirect advisories, all needing major upgrades. 13 direct deps are a major version behind (React 19, Router 7, Vite 8, Tailwind 4, TypeScript 7, ESLint 10). Node 20 in CI and Netlify, 22 locally. | Dependency policy (S8-014): monthly cadence, Dependabot grouped PRs, `npm audit --audit-level=high` in CI with an allowlist for dev-only advisories; plan the Vite 8 + Router 7 majors as their own PRs with the full suite as the gate. | engineering |
| BR-07 | **Editorial throughput** | 30 merges in 30 days, 24 of them touching `src/data`; every content change is a PR with validators, inventory and a full build; review time is the PR cycle (minutes when the owner is present). No content error reached production in Sprint 7 (five defects were caught by gates before merge). | No CMS. Threshold for revisit: more than one non-engineer editor, or content changes blocked on engineering for > 1 working day. See ADR-004. | owner |
| BR-08 | **Production error visibility** | None. No error reporting, no uptime monitor, no route monitor; failures are found by the maintenance script when someone runs it, or by visitors. Recovery time unknown because nothing measures it. | Fix in Sprint 8 (S8-011/012): scheduled post-deploy and daily smoke against production with retained results, and a privacy-safe client error beacon. | engineering |
| BR-09 | **Local build hygiene** | A fresh `rm -rf dist && npm run build` produces no stray files; the stale local `dist/` had 300 macOS " 2" duplicates from an earlier Finder copy. Not in git, not in Netlify's artifact (secret scan: 362 files, 0 matches). | No action beyond the note: never measure from a stale `dist/`. `bench-build` always builds fresh. | engineering |
| BR-10 | **Locale scalability** | `Language = 'en' \| 'es' \| 'fr'` in one module; routes are mounted once per prefix from one table; 27 files still carry `'/es'`/`'/fr'` or `['en','fr','es']` literals (scripts, tests, contentIndex, Seo/App helpers). | Refactor (S8-019): one locale registry that scripts and tests import; prove with a temporary test locale. | engineering |
| BR-11 | **Critical-journey coverage** | 216 node tests, 54 Playwright local, 6 smoke, 68 prod-audit. Journeys covered: browse, book page, buy click, read aloud (unit only), search, collection, journey progress, save, pack signup + delivery, downloads, language switch, games continuation, print. Not covered: newsletter live round-trip (owner-only), Amazon destination availability. | 95% target met for public flows; record the two exclusions with reasons in the readiness assessment. | engineering |
